## **基本原则**

- **命名规则**: 使用 snake_case 命名方式，即全部小写字母，并用下划线（`_`）分隔单词。
- **语言**: 所有名称均使用英文。
- **避免使用保留字**: 不要使用 SQL 保留字作为对象名称。

## **表命名规范**

### **Bronze 层规则**
- 所有名称必须以源系统名称开头，且表名必须与原始名称一致，不得重命名。
- **`<sourcesystem>_<entity>`**  
  - `<sourcesystem>`: 源系统名称（例如：`crm`、`erp`）。
  - `<entity>`:源系统中的确切表名。
  - 例如: `crm_customer_info` → 来自 CRM 系统的客户信息。

### **Silver 层规则**
- 所有名称以源系统名为前缀，表名保持与源系统一致，不允许改名。
- **`<sourcesystem>_<entity>`**  
  - `<sourcesystem>`: 源系统名称（例如：`crm`、`erp`）。
  - `<entity>`: 源系统中的确切表名。
  - 例如: `crm_customer_info` → 来自 CRM 系统的客户信息。

### **Gold 层规则**
- 所有名称必须使用有意义且与业务一致的表名，并以类别前缀开头。
- **`<category>_<entity>`**  
  - `<category>`: 描述表的角色，例如 `dim`（维度表）或 `fact`（事实表）。
  - `<entity>`: 表的描述性名称，与业务领域保持一致（例如：`customers`、`products`、`sales`）。
  - 例如:
    - `dim_customers` → 客户数据维度表。  
    - `fact_sales` → 包含销售交易记录的事实表。

#### **类别命名模式词汇表**

| Pattern     | Meaning                           | Example(s)                              |
|-------------|-----------------------------------|-----------------------------------------|
| `dim_`      | Dimension table                  | `dim_customer`, `dim_product`           |
| `fact_`     | Fact table                       | `fact_sales`                            |
| `report_`   | Report table                     | `report_customers`, `report_sales_monthly`   |

## **列命名规范**

### **代理键** 
- 维度表中所有主键必须使用 `_key` 后缀。
- **`<table_name>_key`**  
  - `<table_name>`: 指该键所属的表或实体名称。
  - `_key`:后缀，用于表明该列是代理键。
  - 例如: `customer_key` → `dim_customers` 表中的代理键。
  
### **元数据列**
- 所有技术列必须以 `dwh_` 为前缀，后跟描述性名称以表明该列的用途。
- **`dwh_<column_name>`**  
  - `dwh`: `dwh_` 前缀专用于系统生成的元数据。
  - `<column_name>`: 表明该列用途的描述性名称。
  - Example: `dwh_load_date` → 系统生成的列，用于存储记录加载日期。

## **存储过程**

- 所有用于加载数据的存储过程必须遵循以下命名模式：
- **`load_<layer>`**.
  
  - `<layer>`: 表示要加载的数据层，例如 `bronze`、`silver` 或 `gold`。
  - Example: 
    - `load_bronze` → 用于将数据加载到 Bronze 层的存储过程。
    - `load_silver` → 用于将数据加载到 Silver 层的存储过程。
